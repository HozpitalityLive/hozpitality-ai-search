# V6.5 — Canonical AI Search Documents

## What changed

- `ai_search_text` is now the canonical flattened search document.
- `metadata` stores structured relationships/attributes.
- V6 FTS includes `ai_search_text` and additional taxonomy fields.
- No large trigram index was added to `ai_search_text`; the existing GIN FTS
  index is the primary fast index for the complete document.
- Professional indexing now includes:
  - job role
  - department
  - job level
  - education
  - current company
  - skills
  - languages
  - industries
  - experience
  - profile/about/tagline
- Article indexing includes category and country relationships.
- Job indexing includes company, country, role, department, level, industry,
  employment type and job type.
- Event/product/FAQ/award/category/post enrichment is included.
- Unknown content types get a safe generic source-row representation.
- Embedding backfill now prefers `ai_search_text`.
- Runtime search keeps deterministic retrieval; the LLM is not called to build
  search documents.

## Production sequence

1. Apply `sql/013_v6_ai_search_document.sql`.
2. Backfill `ai_search_text` and `metadata` in small batches.
3. Rebuild `search_vector_v6` once after the backfill.
4. Run search benchmarks.
5. If semantic search is enabled, regenerate NULL embeddings from the canonical
   search document.
6. Restart/reload the V6 service after deployment.

## Important

The supplied schema was used to build relationship-aware enrichment for the
known Hozpitality tables. The backfill does not expose sensitive user-account
authentication fields.
